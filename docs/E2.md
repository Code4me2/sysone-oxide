# E2: the SIMT GDN backend in the engine (2026-11-13)

Workstream E2 put G1's cuda-oxide SIMT delta rule ([G1.md](G1.md)) into the real engine and ran every accuracy gate
with it, next to the cuTile backend on the same build (branch `ws/e2-simt-engine`, on main at `5fe592e`). SIMT passes
every gate and is now the default on sm_121; every other architecture keeps cuTile until it is validated there.

## What changed

- **Engine op table.** `TileKernels` (`src/engine/kernels.rs`) runs the delta rule on either backend, fixed per
  engine. SIMT: `tree_conv1d_silu` (cuTile) -> `gdn::simt::gates` -> `gdn::simt::chunk_scan` (tinv, slot guard,
  prefix scan, suffix scan) -> `gated_rmsnorm` (cuTile), the launches of `gdn_mixer_with(.., Simt)`. cuTile: unchanged
  (`gdn_prep` stores f32 q/k, `gdn_chunk_scan`). `GraphOp::GdnChunkScan` now takes the whole conv output (SIMT reads
  q, k and v from it; cuTile only its v columns), so the arena plan is unchanged.
- **Selection.** `EngineOptions::gdn_backend: Option<GdnBackend>`; `sysone --gdn-backend auto|tile|simt` (default
  `auto`); `$SYSONE_GDN_BACKEND` in `engine_e2e`, `engine_layers`, `engine_server` and `bench_forward`
  (`--gdn-backend` there too). `auto` = `GdnBackend::default_for_arch`: SIMT on sm_121, Tile elsewhere. The load
  logs `GDN backend simt (default for this architecture) on sm_121` (or `(requested)`), and `/metrics` exports
  `sysone_engine_info{engine="bf16",gdn_backend="simt",arch="sm_121"} 1` (`DecisionEngine::info`). `/health` is
  unchanged (qev's body).
- **No silent fallback.** With SIMT (requested or by default) `TileKernels::new` loads the SIMT module for the device,
  so a missing or stale artifact for the device's architecture fails the engine load with the rebuild command
  (`kernels-simt/build.sh sm_XX`).
- **Scratch.** `GdnScratch::for_engine`: conv and core are arena values, so one-row placeholders; SIMT also drops q,
  k and p. The engine's cuTile scratch used to allocate four full-size WY buffers (`w, u, qd, kd`, 16 KB/token each)
  that the default scan never reads; they are gone for both backends. State slots stay `--max-prefixes`
  (`TileKernels::update` refuses a batch with more prefixes before staging it; the SIMT slot guard writes NaN if a
  replay ever saw more). `GdnScratch::for_plan` (one slot per segment) is not used: at 2 MiB per slot it would cost
  4 GiB at 2,049 segments.

  | largest bucket | cuTile before | cuTile now | SIMT |
  |---:|---:|---:|---:|
  | 16,384 | 1.0 + 1.0 (WY) GiB | 1.00 GiB | 0.63 GiB |
  | 32,768 | 1.51 + 2.0 GiB | 1.51 GiB | 0.76 GiB |
  | 65,536 (server default) | 2.52 + 4.0 GiB | 2.52 GiB | 1.02 GiB |

- **Profile labels.** `Kernels::profile_label` lets the kernels name what they launch: `gdn.simt_gates`,
  `gdn.simt_tinv`, `gdn.simt_slot_guard`, `gdn.simt_scan_prefix`, `gdn.simt_scan_suffix` (ARCHITECTURE §5).
- **Eval harness.** `GDN_BACKEND=tile|simt|auto bash reference/eval/run_sysone.sh`; the run config records the
  requested and the resolved backend.

P1's fused cuTile conv (`tree_conv1d_silu_inv` + `gdn_chunk_scan_conv`, ARCHITECTURE open question 4) was not adopted
for the cuTile backend: it is not bit-identical to the stored-q/k path (fp32 noise, `kernels_gdn::
scan_from_bf16_conv_matches_stored_f32_qk`), so it would change the fallback's numerics and need its own gate runs,
and on sm_121 SIMT replaces that path anyway (it normalises q, k inside its scan and needs no inverse norms). Worth
doing when an architecture is going to stay on cuTile.

The cuTile rows reproduce A1's numbers exactly (the refactor does not change cuTile numerics). **With SIMT the
deep-layer asymmetry that A1 flagged is gone**: at layer31 and norm the median log ratio moves from +2.0% to -0.2/-0.3%
and the worse/better row counts become symmetric (178/167, 81/79 against 326/150, 222/75). Only the GDN backend differs between
the two runs, so that asymmetry is tied to the cuTile delta rule rather than to numerics both backends share
(consistent with G1's state errors: SIMT is below cuTile on every prefix). Relevant to A3's deep-layer diagnosis. Single-row maxima are larger with SIMT at layer15/31/norm (reported, not gated; the maxima are
heavy-tailed rows whose error the reference itself shows at 4.8e-2/6.3e-1/7.5e-1).
